Wire the combination

Save a copy of your working ControlNet graph. Insert Load LoRA on the checkpoint MODEL and CLIP branches:

Checkpoint.MODEL → Load LoRA.model
Checkpoint.CLIP  → Load LoRA.clip
Load LoRA.MODEL  → KSampler.model
Load LoRA.CLIP   → both text encoders’ clip inputs

Keep both text encoders feeding Apply ControlNet, then KSampler. Keep the Canny branch, Empty Latent Image, decoder, and saver. Select PixelArtRedmond15V-PixelArt-PIXARFK.safetensors. LoRA ports · ControlNet conditioning ports.

Set up both runs

Positive: a small white fox sitting beneath a tree, pixel art, PixArFK. Negative: text, watermark. Keep the same reference and Canny thresholds, ControlNet strength 0.8/start 0/end 1, seed 43 fixed, CFG 7, steps 20, euler/normal, denoise 1.0, 512 × 512, batch 1. Use this prompt in both runs; remove the earlier watercolor wording.

Predict and test

Predict whether enabling the adapter will strengthen pixel-art appearance while the ControlNet still guides layout. Run first with both LoRA strengths 0; then change both to 0.8 and run again. This tests the adapter as a whole.

Feedback

If the style changes but layout weakens, report both; the two controls can interact. If there is no visible adapter effect, check the selected file and that neither model nor CLIP branch bypasses Load LoRA.
