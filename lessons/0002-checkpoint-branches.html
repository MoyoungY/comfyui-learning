One checkpoint, three roles

Retrieve

Before looking back: name the two inputs required to decode a sampled latent. Which supplies data and which supplies a model?

Concept

For a standard Stable Diffusion checkpoint, Load Checkpoint supplies three model objects: MODEL for sampling, CLIP for encoding text, and VAE for converting between latent and pixel representations. Official node explanation.

Small workflow fragment

Load Checkpoint
  MODEL ──────────────────────▶ KSampler.model
  CLIP ─▶ CLIP Text Encode ────▶ KSampler.positive
  VAE ────────────────────────▶ VAE Decode.vae

KSampler ── LATENT ──▶ VAE Decode ── IMAGE ──▶ Save Image

The text encoder also takes your prompt. Its output type is CONDITIONING: encoded prompt information, distinct from the CLIP model used to produce it. Pinned source: CLIPTextEncode.

This is a fragment. Negative conditioning and an initial latent are still needed for the complete standard graph. Today, inspect the model branches without generating.

Exercise in your editor

  1. Find Load Checkpoint. If the canvas is empty, double-click empty space and search for it.
  2. Locate its MODEL, CLIP, and VAE outputs.
  3. Trace their wires. If building on an empty canvas, add KSampler, CLIP Text Encode (Prompt), and VAE Decode and wire the three branches above.
  4. Connect the text encoder output to KSampler's positive input.

A blank checkpoint selection means model setup is still needed; it does not prevent inspecting ports. Keep any existing workflow intact.

Debugging prediction

The source supplies a CLIP model; the destination expects CONDITIONING. Insert CLIP Text Encode and supply prompt text. It uses the model to produce prompt data.
